# Documentation standards

Requirements use stable IDs, observable acceptance and REQUIRED FOR LAUNCH priority. Catalogs record durable public behavior; private implementation helpers need no blueprint entry unless they alter architecture. Machine-readable planning catalogs and Markdown views must agree; validate references and regenerate indexes when contract data changes. No TBD, deferred core requirement or invented completion evidence.

Memory is a compact routing cache, never authority over synchronized master. Update only durable decisions, current constraints, state and handoff evidence. An implementation PR includes exact chunk, requirements, authorization/architecture impact, verification and independent findings. Human/legal decisions are explicit blockers with owner/action/affected launch gate. Scope changes require explicit human instruction and reviewed versioned changes across requirement, design, API, frontend, chunks and tests before implementation.

Authority: approved scope and architecture precede this standard. Apply only to the selected chunk; verify against its acceptance criteria and record evidence in its handoff.
