# Frontend standards

Next.js App Router, strict TypeScript, Tailwind tokens and accessible shadcn primitives form one frontend. Route components compose features; features consume generated API contracts through centralized clients. Domain components accept least-privilege DTOs. Presentation never determines payment, ownership, grading or completion authority. Server rendering of private routes uses no shared public cache.

Keep teacher and student graphs free of finance feature imports. Split role navigation and server guards; still authorize each API call. Use explicit loading, empty, permission-denied, validation, stale-data and retry states. Mutation success invalidates affected query keys scoped by actor/student/cohort. Clear private cache on logout/role switch. No tokens in localStorage and no secrets in browser environment. Components and user journeys must map to catalogued API operations before implementation.

Authority: approved scope and architecture precede this standard. Apply only to the selected chunk; verify against its acceptance criteria and record evidence in its handoff.
