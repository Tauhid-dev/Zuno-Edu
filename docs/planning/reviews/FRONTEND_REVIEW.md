## Findings and verified closure

| ID | Original severity | Finding | Final closure evidence |
|---|---|---|---|
| FR01 | High | Account role/status administration lacked a named account directory and current account token. | API-ADMIN-ACCOUNTS and API-ADMIN-ACCOUNT provide identity-only bounded AccountView projections. AdminAccountRoleManager binds both reads and the existing role read. RoleGrantView.version explicitly projects the owning Account.version; both role and status writes compare/increment that counter. Shared locking protects the last active identity administrator against concurrent grant removal or suspension; self-escalation and teacher/admin incompatibility remain forbidden. |
| FR02 | High | First-price creation could not select unpublished or unpriced targets without education privileges. | API-ADMIN-PRICE-TARGETS provides a strict finance-only course/cohort ID/title/lifecycle projection, including draft/unpriced targets. AdminPriceSettings maps those exact IDs to price creation and does not invoke the education directories. Conditional cohort fields, scope-before-pagination and no content/roster hydration are explicit. |
| FR03 | High | File, completion, legal-hold and family mutations lacked readable identifiers or exact concurrency tokens. | FileAssetView now returns its own version. Protected completion history returns the same-enrolment active_override_id and persisted progress_version; review actions use that token and re-read it afterward. Identity-only hold target/state reads exclude financial/file contents, distinguish absent hold_version=0 from an existing hold counter, and serialize first insert/update against purge. AdminFamilyRelationshipsView lists exact guardian-child pairs and independent billing memberships with their own row states/versions; parent FamilyView is unchanged. Frontend bindings distinguish Family creation/reactivation tokens from relationship revocation tokens. The closure recheck also fixed first attendance/assessment writes and delivery closure: authorized reads prove absence, exactly one If-None-Match:* or positive current If-Match is required, and AssignmentDeliveryRule owns a separate token from the immutable assignment definition. |
| FR04 | High | Education workspaces could not name learners or choose the first feedback recipient without identity access. | API-ADMIN-COHORT-LEARNERS returns only cohort/enrolment/student references, first/preferred display name and a coarse education lifecycle label. Its scoped repository projection excludes contacts, family identity, payment data and broad child profiles. Enrolment, attendance, assessment, feedback and completion components bind it; empty feedback lists no longer prevent recipient selection. Teacher workspaces bind the existing assigned roster. |
| FR05 | Medium | Existing read prerequisites were missing from first-use and direct-entry workflows. | Canonical component operations, route operations and input_sources now bind revision-before-course-publication, revision lesson hierarchy before quiz/assignment definition, same-revision assessment references before lesson blocks, cohort/revision/session/closure reads before delivery actions, cohort sessions before session-specific teaching assignment, course/cohort targets before communications, payment detail before first refund, linked family children before parent selection, and roster/assignment rubric before teaching review. | FR06 | High | Operations-only file uploads were required to name an inaccessible curriculum/submission context. | Upload purpose/context rules now resolve submission to the student's own draft, resource to an education-authorized writable revision, and internal/public_asset to the authenticated operations administrator's SessionView.user_id/Account.id.
