## Decisions used for consistent planning

- One modular monolith, Python/FastAPI, explicit application services and framework-independent domain objects; PostgreSQL via SQLAlchemy data mappers and Alembic. One Next.js/TypeScript/Tailwind/shadcn frontend with five role/public route groups. Redis is disposable queue/cache infrastructure; PostgreSQL outbox and job records preserve work.
- Parent registration creates a Family and primary Guardian membership. Guardian-to-child access is explicit, verified and revocable; no automatic linking by matching names/email. Additional guardian linking uses audited administrator verification; parent cannot discover or claim unrelated children. Students have parent-provisioned credentials with no child email requirement. Staff accounts are invited by authorized administration.
- Student name and integer age at registration are required. Last name, preferred name and school are nullable. Store age plus recorded date and require guardian reconfirmation at subsequent enrolment if stale; do not infer an exact birth date. Do not collect health diagnoses or sensitive free-text data by default.
- AUD single upfront card payment for one student/cohort per checkout. Course default fee with explicit cohort override; immutable price/tax snapshot per purchase. No subscriptions, instalments, coupons, marketplace, cart or automatic discounts. An unpaid seat has a 30-minute hold aligned with Checkout expiry. Late verified payment without an available seat becomes PAID_EXCEPTION with a serialized admin decision to allocate a free seat or refund, never an oversold enrolment. Reconciliation remains server-authoritative. Refunds are admin-finance only with full/partial amounts and explicit educational-access disposition.
- Reusable Course curriculum uses immutable published revisions. Cohort pins a revision. Content release gates are cohort-relative. Draft answers, marks and feedback never leak into learner projections. Completion award is a certificate; no independent points/badge gamification.
- One ClassSession per occurrence, UTC instants plus IANA timezone and original local scheduling intent. Materialize finite weekly recurrence into sessions, validate DST ambiguity, and edit individual future sessions. Teacher rescheduling restricted to assigned future sessions at least 24 hours ahead, no capacity/cohort/price changes, no teacher or learner conflicts; admin handles exceptions with reason.
- Zoom native join/start handoff, no embedded Meeting SDK. Meeting references encrypted at rest; host URLs are ephemeral and fetched only for an authorized assigned host. Waiting room enabled, join-before-host disabled, no recording by default. Parent may see schedule and assist a linked child's join, but receives no host privilege.
- Google Calendar mirrors session/event metadata into a dedicated business calendar without pupil roster, family information or Zoom host secrets. Individual stable events are easier to reconcile than a second recurring authority. Parent add-to-calendar exports contain a portal deep link; external edits never mutate the domain schedule.
- Resend sends transactional mail from an authenticated business domain. Durable outbox and Notification delivery ledger separate APIs from mail; optional communications preferences do not suppress required security/payment notices. No child marketing.
- S3-compatible private object storage: quarantine uploads, validate actual file type/size, malware scan, promote immutable objects, issue short-lived downloads after ownership checks. Student uploads limited to PDF, PNG/JPEG, TXT and approved project ZIP (archives constrained and never executed). Learning video is a staff-uploaded MP4 or approved HTTPS video reference; no arbitrary embeds/scripts.
- Admin privileges separate education, finance, identity, operations and security audit. A teacher principal cannot gain financial privileges through additive teacher/admin roles: reject incompatible staff role grants and require a separate admin principal with MFA. Every API and use case rechecks ownership/assignment/state; route guards are presentation only.
- Human decisions are launch gates for final policies/consent language, tax treatment/legal invoice content, approved child age bands, Zoom host licences and production account configuration. Safe technical contracts must remain complete while commercial/legal values are unconfigured. Production enrolment/publishing stays disabled until required settings are approved.

## Verified external constraints

Checked against primary documentation on 11 September 2026. These facts constrain adapters; the application policies above are design decisions.

- Stripe fulfilment must tolerate concurrent duplicate calls and use verified server payment status; browser return is not proof. [Stripe fulfilment](https://docs.stripe.com/checkout/fulfillment).
- Verify Stripe signatures against the original request bytes, handle duplicate deliveries, and do not depend on event order. [Stripe webhooks](https://docs.stripe.com/webhooks).
- Zoom account-owned integration can use Server-to-Server OAuth. Host start URLs grant host authority and must not be exposed to learners; obtain fresh host URLs when needed. [Zoom OAuth](https://developers.zoom.us/docs/integrations/oauth/), [Zoom Meetings API](https://godevelopers.zoom.us/docs/api/meetings/).
- Calendar incremental sync tokens can expire; a 410 response requires a full external mirror resync. PostgreSQL schedule records are never cleared because an external token expired. [Calendar synchronization](https://developers.google.com/workspace/calendar/api/guides/sync).
- Resend's provider idempotency window is 24 hours, so local delivery deduplication must survive beyond it. [Resend idempotency](https://resend.com/docs/dashboard/emails/idempotency-keys).
- Presigned object uploads can overwrite an existing key; use unique staging keys and immutable promoted keys. URLs are bearer credentials. [S3 presigned operations](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html).
- Server Functions and API operations require authorization even when UI access is guarded. [Next.js authentication](https://nextjs.org/docs/app/guides/authentication).
- Deny by default, verify every resource access, and validate uploads independently of filenames. [OWASP authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html), [OWASP upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html).
