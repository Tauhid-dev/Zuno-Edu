# Live class architecture

Zoom is behind LiveClassProvider. Use account-owned Server-to-Server OAuth and native Zoom links. Each ClassSession has one active meeting binding; Course has none. Session is scheduled first in PostgreSQL; an outbox job creates the provider meeting. A provider failure leaves a visible SYNC_ERROR and retry/operations alert; it does not delete the class or fabricate a join URL.

Meeting payload contains course/cohort display label, session start/end/timezone, configured staff host, waiting room on, join before host off and recording off. No child roster, age, school, billing or internal learning notes. Host licensing/capacity and account scopes are launch integration gates. No student Zoom account is required by the platform login design; actual provider joining constraints are validated in staging with child-safe settings before launch.

LiveClassService.get_join_access(actor, session_id) checks active enrolment/linked guardian assistance, session not cancelled, provisioned meeting and join window 15 minutes before start through scheduled end. It returns short-lived handoff metadata with no host privilege; responses are no-store and URLs excluded from logs, analytics and Calendar. Revalidate access for every request. Parents see the schedule and may assist their linked child's join. Teachers start only their assigned session as the configured authorized host, from 30 minutes before start through scheduled end, through get_start_access. Admin operations can repair host bindings but administrative status alone does not expose a host URL unless the principal has an explicit host assignment.

Fetch current host start URL on demand; do not store it in frontend data or email. Provider URL expiration may exceed our access window, so application authorization cannot revoke a copied provider link; cancellation/update and waiting-room admission are the provider controls. Document this real limitation for operational training. Store meeting identifiers encrypted and retain only required references, not reusable host URLs. [Zoom API host URL rules](https://godevelopers.zoom.us/docs/api/meetings/) and [account OAuth](https://developers.zoom.us/docs/integrations/oauth/).

SchedulingService accepts teacher changes only for future assigned sessions at least 24h ahead, within cohort dates, with all assigned teacher and enrolled learner conflict checks and no room for role/price/capacity changes. Admin overrides require education privilege, reason and conflict resolution (not silent overlap). Write new schedule_version and old/new time audit; workers update Zoom and Calendar independently and send version-specific notifications. Multiple changes coalesce to latest desired version. Session cancellation records tombstone, revokes application joins immediately and queues meeting deletion. Timeout before create ID is returned becomes ambiguous; reconcile correlation before retry or request operations repair. Never blindly create a second host meeting.

Acceptance: create/update/cancel, stale retry after cancellation, unauthorized start/join, assignment removed while cached UI remains open, provider timeout, expired host URL, overlapping session and DST transition. Provider-reported attendance is not launch authority; teacher maintains AttendanceRecord.
