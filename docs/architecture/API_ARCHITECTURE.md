# API architecture

Status: DRAFT. Architecture version1.0. This is a complete proposed launch blueprint for human review. No application code is implemented. Canonical machine-readable details: [backend-catalog.json](backend-catalog.json). Requirement authority: [requirements.json](../product/requirements.json). Implementing chunk IDs are assigned by the consolidated Code Blueprint and requirement-to-chunk traceability; no catalog entry may be implemented without that assignment.

REST is namespaced under `/api/v1`; internal WORKER entries are not routable HTTP. Stripe webhook ingress is a dedicated provider-authenticated route using original bytes. The API catalog is the source for versioned OpenAPI schemas and generated TypeScript clients during implementation. Backend validators and generated frontend types share contracts; handwritten duplicate DTO interfaces are forbidden.

Each operation defines method/route, roles, relationship/state authorization, field-level request and response schema, concrete public service operation, domain/port dependencies, errors, requirements and consumer. GET reads cannot mutate business state. Mutations use explicit lifecycle routes rather than arbitrary state/property mass assignment. Responses use200 with declared DTO,202 for durable accepted work and204 for Empty; no successful Empty response contains JSON. Creation currently uses200 consistently to simplify named contract semantics. `Accepted.status_url` is a relative same-origin authorized job URI in implementation, not an unrestricted external redirect.

Path UUIDs are opaque and parsed before scoped lookup. Query ranges are bounded and ordered cursors include principal, scope, filter and expiry. List limits default25, maximum100. Unknown fields fail422. Strings are bounded UTF-8; optional blank values normalize null; explicit null clears nullable fields while PATCH omission leaves values unchanged. Dates are ISO8601, instants RFC3339 UTC and scheduling also captures IANA zone plus original local time/offset. Money is integer AUD minor units. Enum values are closed and schema evolution must be reviewed.

`If-Match` carries the numeric aggregate version for versioned mutations; version conflicts return409 before changing state. Current-session logout and own-device revocation are idempotent without a version precondition. `Idempotency-Key` is required where declared, including checkout, submitted work, refunds, paid-exception resolution and durable creation/retry actions. Key scope is principal+operation+key and request-body hash; same body replays safe result, changed body409. Financial idempotency persists90days and ordinary operations7days; provider event/reference deduplication outlives replay windows. A duplicate request must not reissue secrets or weaken authorization; current principal scope is checked before replay.

Authentication uses an opaque secure HttpOnly SameSite=Lax cookie under the same origin with CSRF token and Origin verification for state-changing browser calls. CORS is restricted to approved same-origin deployment. No localStorage access/refresh token pattern is used. A login result is AuthOutcomeView: full authenticated session OR five-minute MFA challenge OR ten-minute restricted MFA setup token. Staff acceptance does not grant portal authority until TOTP proof succeeds. MFA verification accepts a TOTP code or one unused recovery code; both consume challenge and update replay state atomically with full-session issuance. Expired/consumed credentials never replay.

API errors use the named Error schema with stable code, safe message, request_id and optional field_errors/retry_after_seconds. Unauthenticated401, prohibited capability403, inaccessible resource404, domain/version/idempotency conflict409, malformed validated input422, abuse429 and provider unavailable503. The envelope never returns stack traces, private resource existence, raw SQL, provider credentials or child data. Retry-After accompanies rate limits and controlled transient outages. Structured internal logs use correlation IDs rather than request bodies.

Public pages may use short bounded caches keyed by publication version. All private profile/work/money/meeting/token responses use Cache-Control:no-store. Returned links are approved HTTPS provider handoffs or same-origin portal paths; return_path is an allowlisted relative path. Presigned storage URLs are bearer credentials, expire quickly and carry no reusable storage credential. Staff/student/provider URL redirects are excluded from analytics and use a no-referrer policy.

Raw Stripe signature verification occurs before parsing into a verified event. Supported event type and provider IDs are validated, provider+event is inserted once, and processing uses server retrieval to resolve authoritative state. Duplicate and out-of-order events are expected. Browser success/cancel return only drives UI status polling; it never activates enrolment. Internal background jobs use current source state, explicit capability and idempotent public service operations.

Contract tests must validate actual response fields, positive and negative role/resource cases, unknown fields, cursor tampering, versions, idempotency and complete error codes. Changes that remove/rename required fields or alter authorization are architecture/scope changes after lock. New durable APIs require approved requirement and Code Blueprint/chunk assignment before implementation.
